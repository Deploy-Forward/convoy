How it works

  1. 01 · Attach

    Attach one MCP: https://convoy.bot/mcp. A named thread is a --root binding, not a second MCP URL.

  2. 02 · Onboard / roster

    Name the harnesses you already have. Convoy reports PATH truth and does not invent a roster.

  3. 03 · Send / feed / context

    send is headless synapse flow: pointers in, compact card out. feed and context are stamps and pointers, not vendor transcripts.

  4. 04 · bring_up / open

    For visible TUIs, use bring_up or open: one isolated Windows Terminal window per named thread with split panes. Grok Bot is not a window.

Objects

thread

Durable circuit keyed by convoy_id. One visible thread stays authoritative.

neuron

BYO native CLIs: grok, claude, codex, cursor-agent, agy, hermes, pi.

synapse

One native send into one neuron. Live send refuses stealing an interactive --resume flow (no-steal).

convoy contract

feed + seats + convoy_id. Unknown values remain JSON null; no invented usage or session numbers.

Honesty

  • Public MCP stays attach-first. Core tools are stable; in-tree extras like hide and install can lag on a deployed process.
  • BYO harness only, no wraps. Convoy is not ola-brain or UltraCode-Shim as the product surface.
  • Native live send is not overclaimed here; use bring_up when you need visible interactive sessions.
